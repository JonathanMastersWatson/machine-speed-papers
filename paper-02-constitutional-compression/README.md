## What This Paper Is

This paper asks what happens to governance when the systems it governs stop waiting for it.

It derives — from first principles, without assuming any specific architecture or implementation — a minimal constitutional core for machine-speed execution: the smallest mechanism capable of performing governance at the one moment governance can still be causal.

The central finding: governance does not disappear under machine-speed pressure. It redistributes. Interpretation migrates upstream. Accountability migrates downstream. Enforcement compresses to a minimal kernel at the execution boundary — six primitives, no reasoning, one question answered before the action commits.

---

## The Six Primitives

| Primitive | Function |
|---|---|
| Proposed action | The object being governed |
| Compiled standard | The basis for permit or deny |
| Authority check | Confirmation the proposer has standing |
| Evaluation act | The comparison of proposal against standard |
| Binding output | Permit or deny, obeyed by the system |
| Fail-safe behavior | Pre-declared default when evaluation cannot complete |

## Series Context

This is Paper 2 in The Machine Speed Papers.

**Paper 1 — Execution-Boundary Governance: A Runtime Control Model for Autonomous Systems**
Introduces the execution boundary, the Executable Governance Kernel (EGK), and the five properties any boundary governance mechanism must satisfy. Grounds the argument in latency physics, liability doctrine, and insurance underwriting.

**Paper 2 — Constitutional Compression (this paper)**
Derives the minimal constitutional core from first principles. Asks not what a governance kernel should contain, but what governance itself requires when stripped to its irreducible function. Tests the result against Locke, Hobbes, Rawls, and administrative law. Finds the kernel is not bureaucratic machinery but a constitutional mechanism — one that mechanizes a question every major tradition of legitimate authority asks.

**Paper 3 — Evidence Systems (forthcoming)**
Asks: if the kernel makes a determination, how do we prove it occurred? Addresses the independent witnessing infrastructure the accountability interface requires.

## Key Claims

1. The traits that define human governance are adaptations to a speed regime, not fundamental properties of governance itself.

2. Under machine-speed pressure, governance redistributes rather than disappears — interpretation upstream, enforcement at the boundary, accountability downstream.

3. A minimal kernel of six primitives is derivable from first principles as the smallest mechanism capable of governance at the execution boundary.

4. That kernel cannot be a reasoning system — inference fails every requirement the boundary imposes.

5. The kernel mechanizes a question multiple incompatible constitutional traditions all ask, and depends on none of them in particular.

6. The hardest open question is legitimacy: who compiles the constraints the kernel enforces, and what makes that process accountable?

---

## What This Paper Is Not

- An argument for removing human oversight. Human judgment is irreplaceable — it is the upstream compilation process the entire architecture depends on.
- An argument that machine-speed governance is superior to interpretive governance. Mismatch, not inferiority, is the finding.
- An implementation specification. This paper derives what must exist. How it gets built is a separate question.
